## 4.1 Lingkungan Implementasi

Sistem informasi pencatatan stok dan barang masuk **Edu Coffee** dikembangkan menggunakan pendekatan arsitektur berlapis berbasis **Flask** dan **SQLite** dengan antarmuka server-side rendering (Jinja2) serta server WSGI **Waitress** untuk lingkungan produksi[cite: 14, 16, 18]. Pengembangan dilakukan di lingkungan Windows menggunakan Python 3.10+, Visual Studio Code, dan Git, dengan pemisahan konfigurasi sensitif melalui variabel lingkungan (`APP_ENV`, `SECRET_KEY`, `TOKO_DB`, dan `COOKIE_SECURE`) agar tidak ada kredensial atau berkas basis data operasional yang tersimpan di repositori[cite: 18].

| Komponen / Paket | Versi / Spesifikasi | Peran dalam Proyek Edu Coffee |
| :--- | :--- | :--- |
| Python | 3.10+ (`.venv` lokal) | Bahasa runtime aplikasi, pengujian, dan skrip utilitas |
| Flask | Terkunci di `requirements.txt` | Kerangka aplikasi web, routing, sesi, dan template |
| Werkzeug | Terkunci di `requirements.txt` | Hashing kata sandi (`generate_password_hash` / `check_password_hash`) dan utilitas HTTP |
| Waitress | Terkunci di `requirements.txt` | Server WSGI produksi untuk menjalankan objek `app:app` |
| pytest | `9.1.1` (`requirements-dev.txt`) | Kerangka pengujian otomatis unit, alur HTTP, akses peran, dan rilis |
| SQLite | Bawaan Python (`sqlite3`) | Penyimpanan relasional lokal dan pencadangan via `Connection.backup()` |

Asisten AI digunakan secara terkendali sebagai alat bantu draf kode, penyusunan test case, perapihan bahasa dokumentasi, dan penelusuran ide pengujian selama pengembangan[cite: 11, 21]. Setiap keluaran AI selalu ditinjau secara manual, diuji melalui `pytest` maupun mutasi kode, dan dicatat keputusannya (`Terima`, `Ubah`, atau `Tolak`) beserta catatan kesalahan pada Jurnal Vibe Coding sebelum diintegrasikan ke repositori[cite: 11, 21].
