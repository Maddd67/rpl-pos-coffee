# Kesepakatan Tim — Proyek Coffee Shop POS ("KopiKita")

## 1. Identitas
* **Proyek / Klien:** Aplikasi POS & Manajemen Stok "KopiKita Coffee Shop"
* **Anggota dan Peran:**
  * [Nama Mahasiswa A] — Product Owner & Developer
  * [Nama Mahasiswa B] — Scrum Master & Developer
  * [Nama Mahasiswa C] — Developer / Reviewer

## 2. Komunikasi
* **Kanal utama:** WhatsApp Group & Discord Server
* **Waktu Daily Scrum (15 menit):** Senin–Jumat, pukul 20.00 WIB (Online)
* **Batas waktu membalas pesan:** Maksimal 3 jam pada jam kerja (08.00–21.00 WIB)

## 3. Aturan Git
* Tidak ada push langsung ke branch `main`. Semua perubahan wajib melalui Pull Request (PR).
* **Penamaan branch:** `fitur-namafitur`, `perbaikan-namabug`, `docs-namadokumen` (contoh: `fitur-katalog-kopi`, `docs-kesepakatan`).
* Setiap PR wajib ditinjau dan disetujui (*Approve*) oleh minimal 1 anggota lain sebelum di-merge.
* Pesan commit harus informatif dan menjelaskan isi perubahan (contoh: `git commit -m "Tambah route pemesanan kopi"`).

## 4. Aturan Penggunaan AI
* Setiap pembuatan atau modifikasi kode menggunakan AI wajib dicatat di Jurnal Vibe Coding pribadi.
* Dilarang keras menempelkan data pribadi klien, kredensial/password, atau API Key ke dalam prompt AI.
* Kode hasil sintesis AI wajib dibaca, dipahami, dan diuji lokal secara mandiri sebelum di-commit.

## 5. Definition of Done (DoD)
Sebuah fitur atau modul dianggap **Selesai (Done)** apabila:
1. Memenuhi seluruh kriteria penerimaan (*acceptance criteria*) yang disepakati.
2. Kode telah diuji secara lokal dan berjalan bebas dari error.
3. PR telah ditinjau dan mendapatkan *Approve* dari minimal 1 rekan tim.
4. Jurnal Vibe Coding pribadi telah diperbarui terkait fitur tersebut.
5. Dokumen terkait atau komentar kode telah disesuaikan.

## 6. Jika Ada Masalah
* **Anggota tidak aktif:** Jika tidak merespons dalam 24 jam tanpa keterangan, Scrum Master akan menghubungi secara personal. Bila berlanjut > 3 hari, masalah dilaporkan kepada Dosen Pengampu.
* **Perbedaan pendapat:** Didiskusikan bersama dalam forum tim secara objektif. Jika tidak menemui mufakat, keputusan akhir berada di tangan Product Owner demi kepentingan produk/klien.
